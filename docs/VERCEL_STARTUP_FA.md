# رفع خطای راه‌اندازی Vercel

پیام «اجرای سایت آماده نیست» از شکست راه‌اندازی API می‌آید و علت دقیق را به‌تنهایی مشخص نمی‌کند. در نسخهٔ اصلاح‌شده، پاسخ `/api/health` در این حالت کد مشخص دارد؛ دادهٔ اتصال و کلید ورود در پاسخ مرورگر نمایش داده نمی‌شوند.

| کد | بررسی لازم |
| --- | --- |
| `AUTH_SECRET_MISSING` | متغیر `AUTH_SECRET` برای محیط همان استقرار تنظیم نشده است. |
| `DATABASE_URL_MISSING` | `DATABASE_URL` یا نام سازگار `scdule_DATABASE_URL` تنظیم نشده است. |
| `DATABASE_CONNECTION_FAILED` | نشانی اتصال، رمز، دسترس‌پذیری سرویس PostgreSQL و تنظیم SSL ارائه‌دهنده بررسی شوند. |
| `DATABASE_SCHEMA_FAILED` | پایگاه داده قابل اتصال است، اما اجرای ساختار جدول‌ها شکست خورده است؛ خطای SQL و مجوز کاربر پایگاه داده در لاگ بررسی شود. |
| `APP_STARTUP_FAILED` | خطای دیگری هنگام واردکردن ماژول‌ها یا راه‌اندازی برنامه رخ داده است؛ Runtime Logs لازم است. |

## مسیر اصلاح

1. پروژهٔ `schdule` را در Vercel باز کن و وارد **Settings → Environment Variables** شو.
2. وجود `AUTH_SECRET` و اتصال PostgreSQL را برای **Production** بررسی کن. اگر آدرس استقرار از نوع Preview است، متغیرها باید برای **Preview** هم فعال باشند.
3. مقدار `DATABASE_URL` باید رشتهٔ اتصال PostgreSQL به **همان پایگاه دادهٔ اصلیِ موجود** باشد. برنامه ابتدا `DATABASE_URL` و سپس `scdule_DATABASE_URL` را می‌خواند؛ مقدار قدیمی یا نادرست در اولی، بر مقدار درست دومی اولویت دارد. مقدارها را در چت، گیت یا لاگ قرار نده.
4. کلید `AUTH_SECRET` موجود را حفظ کن. اگر اصلاً وجود ندارد، ابزار `node scripts/prepare-vercel-env.mjs` فایل محلی و نادیده‌گرفته‌شدهٔ `.local/vercel.env` را ایجاد می‌کند؛ کلید تصادفی را فقط در تنظیمات Vercel وارد کن. این فایل نباید آپلود یا کامیت شود.
5. از **Deployments → منوی سه‌نقطهٔ آخرین استقرار → Redeploy** استفاده کن. تغییر متغیرهای محیطی، استقرار قبلی را به‌روزرسانی نمی‌کند.
6. اگر خطا ماند، در بخش **Logs** همان محیط، خط `Application initialization failed` و `cause_code` را بررسی کن. برای نمونه، `28P01` مربوط به احراز هویت PostgreSQL و `42501` مربوط به مجوز دسترسی است. متن خطا را بدون رمز، توکن و نشانی اتصال به اشتراک بگذار.
7. پس از اصلاح، `/api/health` باید JSON با `ok: true` و `storage: "postgresql"` بدهد. بعد از ورود، وجود اطلاعات قبلی حساب را نیز بررسی کن؛ موفقیت Build به‌تنهایی کافی نیست.

این مسیر هیچ دادهٔ آزمایشی وارد نمی‌کند و دیتابیس واقعی را با حافظهٔ موقت جایگزین نمی‌کند. کدهای تفکیک‌شده تنها بعد از انتشار این تغییر در استقرار آنلاین دیده می‌شوند؛ نسخهٔ آنلاین قبلی ممکن است همچنان پیام عمومی نشان دهد.

منابع رسمی: [متغیرهای محیطی](https://vercel.com/docs/environment-variables/managing-environment-variables)، [Redeploy](https://vercel.com/docs/deployments/managing-deployments)، [Runtime Logs](https://vercel.com/docs/logs/runtime).
