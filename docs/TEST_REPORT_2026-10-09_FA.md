# گزارش تست سایت NOVA — ۱۴۰۵/۰۷/۱۷

تست‌های فشار در سرور جداگانهٔ محلی روی پورت 3002، با داده‌های حافظه‌ای و پروفایل جداگانهٔ مرورگر Edge اجرا شدند. پس از اصلاحات، سرور اصلی روی پورت 3001 با نسخهٔ پشتیبان کامل حافظه راه‌اندازی مجدد شد؛ شناسه‌ها و اطلاعات قبلی حفظ شدند. داده‌های مرورگر کاربر دست‌کاری نشدند.

## دامنهٔ بررسی

بازشدن و دریافت محتوای تمام ۲۳ سربرگ ناوبری بررسی شد: داشبورد، امروز، تمرکز، کارها، در انتظار، پروژه‌ها، جلسات، تقویم، بانک آیتم‌ها، روتین‌ها، سلامت، روابط، مالی، معنویت، مناسبات مذهبی، حوزه‌ها، منابع، آرشیو، برنامهٔ هفتگی، هدف‌ها، مرور و تنظیمات.

در بانک، بارگذاری همهٔ ۳٬۲۴۸ ردیف، نبود iframe، عرض خوانای عنوان، تیک و برداشتن تیک، انتقال انجام‌شده‌ها به انتهای دسته، اتصال به تسک سرور، همگام‌شدن کارت داشبورد، ویرایش عنوان، حذف و بازگردانی، جستجو و نمایش در عرض ۳۹۰ پیکسل آزموده شدند. عنوان در دسکتاپ ۵۰۲ و در موبایل ۳۷۹ پیکسل عرض داشت؛ عرض سند موبایل از ۳۹۰ پیکسل تجاوز نکرد.

ثبت، ویرایش و حذف تسک، پروژه، رویداد، هدف، عادت، برنامهٔ هفتگی، ایده، یادداشت روزانه، حساب، تراکنش، بدهی و موارد ماژول مرور بررسی شدند. جریان جلسه به تسک، روتین معنوی به ماتریس عادت‌ها، پیگیری روابط به تسک، ثبت سلامت، منبع به اقدام، اتصال هدف و پروژه، مناسبت به تقویم و تسک آماده‌سازی، تعهد مالی به تسک و تقویم، تنظیمات و نمای ذخیره‌شده نیز آزموده شدند.

این گزارش به معنی آزمودن تمام ترکیب‌های ورودی و تک‌تک دکمه‌های فرعی سایت نیست؛ پوشش مرورگر برای سربرگ‌ها و گردش‌های اصلی بانک، و پوشش API برای عملیات اصلی بخش‌هاست.

## نتایج فشار

در اجرای ثبت‌شده، ۵۰۰ تسک آزمایشی به داده‌ها اضافه شد و مجموعه هنگام فشار ۵۱۱ تسک داشت. درخواست‌ها بین داشبورد، صفحه‌بندی کارها، تقویم، کنترل هدف‌ها، منابع، سلامت، روابط، مالی، ماتریس عادت‌ها و سلامت سرور پخش شدند.

- تعداد درخواست: ۱۰۰۰
- هم‌زمانی: ۲۵
- خطا: صفر
- زمان کل: ۱۴۲۷ میلی‌ثانیه
- نرخ تقریبی: ۷۰۱ درخواست در ثانیه
- میانهٔ پاسخ: ۳۴ میلی‌ثانیه
- صدک ۹۵: ۵۱ میلی‌ثانیه
- بیشترین زمان پاسخ: ۶۷ میلی‌ثانیه

این اعداد مربوط به همین رایانه و حالت حافظه‌ای محلی‌اند؛ پیش‌بینی ظرفیت PostgreSQL یا استقرار عمومی نیستند.

## مشکلات پیدا و اصلاح‌شده

1. کد شروع صفحه به جدول قدیمی حذف‌شده ارجاع می‌داد و خطای null ایجاد می‌کرد؛ محافظ وجود عنصر اضافه شد.
2. فونت اینترنتی می‌توانست اجرای اولیه را معطل کند؛ بارگذاری آن از شروع صفحه جدا شد.
3. ماتریس عمومی روتین‌های معنوی را نشان نمی‌داد؛ اکنون از روتین‌های مشترک می‌خواند و ثبت روز آن‌ها را هم پشتیبانی می‌کند.
4. تکمیل یا بازکردن مجدد تسک پیگیری در وضعیت تعهد روابط دیده نمی‌شد؛ وضعیت نمای روابط از تسک مرتبط محاسبه می‌شود.
5. سال، ماه و روز نامعتبر ماتریس کنترل کافی نداشت؛ اکنون پاسخ 400 داده می‌شود.
6. تطبیق بانک با صدها تسک جستجوی تکراری داشت؛ نمایهٔ شناسه و عنوان اضافه شد.
7. کلیک حذف حین ذخیرهٔ عنوان می‌توانست با پایان ذخیره تداخل کند؛ عملیات همان ردیف تا پایان ذخیره غیرفعال می‌شود.

8. ویرایش و حذف روتین معنوی از مسیر عمومی عادت‌ها پاسخ 404 می‌داد؛ اکنون دادهٔ مشترک ویرایش و حذف می‌شود و منبع قدیمی نیز پاک می‌شود تا روتین حذف‌شده دوباره ساخته نشود.
9. داده‌های حالت محلی با ری‌استارت از بین می‌رفتند؛ ذخیرهٔ اتمی روی دیسک قبل از ارسال پاسخ اضافه شد. فایل خراب باعث توقف راه‌اندازی می‌شود تا دادهٔ قبلی با نمونهٔ اولیه جایگزین نشود.

اصلاحات رابط در خروجی dist و اصلاحات سرور روی پورت 3001 فعال‌اند. پیش از ری‌استارت، تمام حافظه مستقیماً از سرور خوانده و در `backups/pre-restart-memory.json` پشتیبان‌گیری شد. حفظ تمام فیلدهای تسک‌ها، پروژه‌ها، رویدادها، تنظیمات و تمام داده‌های V11 تأیید شد. تست تعاملات پس از راه‌اندازی نیز موفق بود.

اسکریپت `scripts/check-server-persistence.mjs` روی سرور موقت 3003، حفظ شناسه و وضعیت تسک، عنوان و لاگ روتین و باقی‌ماندن حذف‌ها پس از دو ری‌استارت واقعی را تأیید کرد. این تست از فایل موقت جدا استفاده می‌کند.

## محدودیت‌ها و شواهد

PostgreSQL، احراز هویت در حالت استقرار واقعی، اتصال واقعی OpenAI و ظرفیت شبکهٔ بیرونی در این تست تأیید نشده‌اند. دوام دادهٔ محلی پس از ری‌استارت تأیید شده است. ذخیرهٔ JSON برای اجرای محلی تک‌کاربره است؛ استقرار عمومی همچنان به PostgreSQL نیاز دارد. سرور و مرورگر آزمایشی پس از پایان خاموش شدند و داده‌های آزمایشی دور ریخته شدند.

نتایج خام در `test-results/api-load-audit.json` و `test-results/browser-audit.json` و تصاویر در `test-results/bank-desktop.png` و `test-results/bank-mobile.png` هستند.

اسکریپت‌ها:

```powershell
npm run build
npm run qa
npm run smoke
node scripts/check-interactions.mjs
node scripts/check-local-store.mjs
node scripts/check-server-persistence.mjs
```

برای تست سنگین، سرور جدا روی پورت 3002 لازم است؛ `scripts/api-load-audit.mjs` فقط همین پورت را می‌پذیرد و دادهٔ آزمایشی می‌سازد. `scripts/browser-audit.mjs` به مرورگر آزمایشی جدا با پورت DevTools 9226 متصل می‌شود و دادهٔ مرورگر همان مبدأ آزمایشی را پاک می‌کند.
